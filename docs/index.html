2. Wat gebeurt er dan?

  1. Ontbrekende softwareDe starter zoekt Python (ook buiten je PATH) en installeert Python, git en Ollama als ze ontbreken — via winget, Homebrew of je pakketbeheerder.
  2. Code ophalenDe repository wordt naar je thuismap gekopieerd, of bijgewerkt als je hem al hebt.
  3. Python-omgevingEen eigen virtual environment, zodat je systeem-Python ongemoeid blijft.
  4. Installeren en klaarzettenpython main.py installeert de dependencies, haalt de Ollama-modellen op en bouwt eenmalig de semantische index.
  5. App opentJe browser gaat naar http://localhost:8501. Stoppen doe je met Ctrl+C.

De eerste keer duurt het langer (modellen zijn enkele GB’s). Daarna start de app snel.

4. Kan het op een telefoon?

Zoeken kan meteen, hier op deze site. De zoeklaag van de app is een opzoekactie over een paar honderd definities — klein genoeg om in je browser te draaien. Geen installatie, geen terminal, werkt op elke telefoon:

🔍 Definities opzoeken werkt op je telefoon

Wat daar ontbreekt is de taalmodel-laag: antwoorden formuleren, vervolgvragen begrijpen, verwijzingen volgen. Dat draait lokaal en heeft een computer nodig.

De hele app op een telefoon draaien: nee. Het is een Python-server met een taalmodel ernaast. iOS staat het niet toe dat een app zomaar programma's uitvoert, en een .bat-bestand is sowieso Windows-only — daarom gebeurt er niets als je het op je iPhone opent. Op Android kan het technisch via Termux, maar de modellen van enkele gigabytes maken dat onpraktisch.

Wel: de app op je laptop, het scherm op je telefoon — en dat werkt vanzelf. python main.py luistert standaard ook op je lokale netwerk. In de app staat onder 📱 Op je telefoon openen het adres én een QR-code; scannen en je bent er. Laptop en telefoon moeten wel op hetzelfde wifi zitten.

Liever niet? python main.py --local-only houdt de app op je eigen computer. Let op: met de standaard kan iedereen op hetzelfde netwerk de app openen — prima op je eigen wifi, niet op openbare wifi. Windows vraagt de eerste keer of Python door de firewall mag; sta dat toe voor particuliere netwerken, anders kan je telefoon er niet bij.

Alleen op deze computer
python main.py --local-only

5. Werkt er iets niet?

“python wordt niet herkend” of “command not found”

Python staat niet in je PATH. Installeer Python opnieuw en vink op Windows “Add python.exe to PATH” aan. Daarna PowerShell of Terminal opnieuw openen.

“Program 'python.exe' failed to run: The system cannot find the path specified”

Windows vindt wél een python.exe, maar die verwijst nergens heen: de Microsoft Store-alias. Draai where.exe python en kijk wat eruit komt — dat verschilt per laptop. Zie je alleen een pad met \WindowsApps\, dan staat er geen Python en moet je die eerst installeren. Zie je daarnaast een echt pad, dan is Python er wel en staat de alias er alleen vóór; die zet je uit bij Instellingen → Apps → Geavanceerde app-instellingen → App-uitvoeringsaliassen. Het uitklapblok “Python werkt niet” bij stap 1 loopt beide gevallen af — en de starter doet dit allemaal zelf.

De .bat wordt geblokkeerd, maar de commando's werken wel — hoe kan dat?

Alles wat je browser downloadt krijgt van Windows een merkteken (“afkomstig van internet”). Veel organisaties blokkeren het uitvoeren van precies díe bestanden. Het script dat je met irm … -OutFile ophaalt wordt door PowerShell zelf weggeschreven en krijgt dat merkteken niet, dus dat draait wel. Beide routes doen exact hetzelfde; gebruik gewoon degene die bij jou werkt.

Windows Security blokkeert het dubbelklikbestand

Op beheerde laptops mag een gedownload script vaak helemaal niet draaien; “Toch uitvoeren” verschijnt dan niet eens. Gebruik de handmatige commando's bij stap 1 (“Wordt alles geblokkeerd?”) — die zijn niet te blokkeren, want er wordt niets uitvoerbaars gedownload.

“This script contains malicious content and has been blocked by your antivirus software”

Je virusscanner blokkeert scripts die rechtstreeks vanaf internet draaien. Dat is beleid, geen fout in het script. Gebruik de handmatige commando's bij stap 1 (“Wordt alles geblokkeerd?”): die hebben geen script nodig en worden niet geblokkeerd.

“No suitable Python runtime found” van de py-launcher

De py-launcher staat op je machine zonder geregistreerde Python. Dat is geen probleem: gebruik python in plaats van py, precies zoals in de commando's bij stap 1. Het startscript slaat een kapotte launcher sinds kort zelf over.

Op mijn telefoon blijft het scherm zwart en daarna volgt een time-out

De pagina laadt wel, maar de verbinding die de app daarna nodig heeft komt niet tot stand. Test eerst op de laptop zelf: open daar het netwerkadres (http://192.168.x.x:8501, niet localhost). Werkt dat niet, probeer dan een van de andere adressen die het paneel toont. Werkt het op de laptop wél, dan is het één van drie: clientisolatie op het wifi-netwerk (veel gast- en universiteitsnetwerken verbieden verkeer tussen apparaten — test met de hotspot van je telefoon), de firewall die Python blokkeert, of een verkeerd adres door een VPN of Docker. Controleer ook of je telefoon op wifi zit en niet op 4G/5G. Het paneel “Zwart scherm of server reageert niet?” in de app loopt dit met je af.

Ik wil de app op mijn telefoon of tablet bekijken

Dat werkt zonder extra stappen: start hem op je laptop met python main.py en open het adres uit het paneel 📱 Op je telefoon openen in de zijbalk, of scan de QR-code die daar staat. Beide apparaten moeten op hetzelfde wifi-netwerk zitten. Zie stap 4.

Er opent geen browser

Kijk in de terminal: daar staat de URL (meestal http://localhost:8501). Klik die aan of plak hem in je browser.

Het LLM-antwoord blijft lang leeg

De eerste keer laadt het taalmodel; de app toont een teller. Duurt het daarna nog steeds lang, kies dan een kleiner model in de zijbalk (qwen3:4b of qwen3:1.7b) en meet met python main.py --benchmark-llm.

Ik wil geen Ollama installeren

Hoeft niet. De app beantwoordt vragen dan uit de lokale documentatie; alleen de LLM-formulering en de semantische zoeklaag zijn dan uit.

Poort 8501 is al bezet

Start met een andere poort: python -m streamlit run app_streamlit.py --server.port 8502.
